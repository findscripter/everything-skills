# 我用《永乐大典》的思路，重新组织了 500 个 AI Agent 技能

## 起点：技能仓库都在堆列表

这一年 AI Agent 的"技能"（Skill）火了起来。一个技能就是一个文件夹，里面一个
`SKILL.md`，告诉 Claude、Codex、Cursor 这类智能体"什么时候、怎么做某件事"。
于是 GitHub 上冒出一大批技能仓库，有的几万 star，收录上千个技能。

但我用着用着发现一个共性问题：**它们几乎都是一长串平铺列表**。

- 分类混乱：同一个技能能塞进三五个分类。
- 检索困难：你不知道该去哪个分类下找。
- 技能孤立：只有一堆条目，没有"谁是谁的前置""哪些能组合"这种关系。

这不是某一个仓库的问题，是"用列表组织高度交叉的知识"这件事本身的问题。

## 一个很旧的主意：类书

中国古代有一类书叫**类书**——《永乐大典》《四库全书》《艺文类聚》都是。它们
解决的正是"海量、交叉的知识怎么组织"：

- **事以类聚**：按主题分门别类。
- **互见法**：一个条目和多个相关条目互相"参见"，化解交叉分类。
- **总目 + 分目 + 索引**：多条路径检索。

这套一千多年前的方法论，和"技能"这种高度交叉的知识形态，意外地契合。

但我得诚实说一句：**类书是"没有搜索引擎的时代"的产物**。它那套庞大人工目录，
本质是在解决"没有 Ctrl+F 时怎么找东西"。今天搜索已经解决了检索——所以我没有
照搬，而是**留下它的魂，换掉它的骨**。

## 关键转折：受众是 AI，不是人

最重要的一个判断：这个库是给 **AI Agent** 用的，不是给人读的百科。

而 Agent 发现技能的方式，是**读每个技能的 `description` 去匹配**——它根本不会
"浏览目录"。这一下就决定了三件事该怎么做：

1. **目录是给人类维护者的，发现靠元数据。** 所以我没用"天-地-人/乾坤五行"那种
   好看但语义为空的分类（Agent 看不见，贡献者也猜不到该放哪），而是用 11 卷
   **内容可预测**的功能域，并配一份 `taxonomy.json` 受控词表——类名越界，构建
   脚本直接报错。机器把"分类规范"焊死，不靠贡献者自觉。

2. **互见不是把技能复制到多个分类，而是做成一张图。** 每个技能的 frontmatter 里
   有 `requires`（前置）/`related`（相关）/`combines_with`（组合）三种关系。一个
   零依赖脚本把它们汇成一张知识图谱：

   ![互见图谱节选](showcase-graph.md)

   （上图是"董事会/财务"这一簇的真实截取——你能直接看出"做董事会材料"需要
   "财务模型"、可以组合"数据叙事"。全库有 2674 条这样的关系边。）

3. **索引、目录、图谱、插件清单全部自动生成。** 手工维护多套索引必然腐烂；让机器
   从 frontmatter 重建。

## 怎么填进去 500 个的？——诚实地讲

我没有手写 500 个技能。**这是一个"策展"项目，不是"原创"项目**，我觉得这点必须
说在前面，否则就是耍流氓。

我做的事是：把 anthropics/skills、trailofbits/skills、wshobson/agents、
K-Dense（科学）、各家行业库等十来个高 star 仓库**克隆下来**，写脚本**逐条过滤
许可**（专有 / GPL / 非商用 / 无许可的一律排除），再用多智能体流水线**精选、
翻译重写成中文、适配到我的规范、补上触发词和互见关系**。

每一条都带 `source` 和 `source_license`，自动汇入一份署名清单。CC-BY-SA 的来源
（trailofbits）改编后仍按 ShareAlike 提供。换句话说，**署名和合规是这个项目的
一等公民**，不是事后补的。

所以它的价值不在"我造了 500 个技能"，而在：**中文优先**（绝大多数大库是纯英文，
这是空白）、**体系化的分类与互见**、**逐条溯源可信**、以及**机器可校验的规范**。

## 它能直接用

仓库本身是一个 Claude Code 插件市场：

```
/plugin marketplace add <仓库地址>
```

11 卷对应 11 个插件，可以整库装，也可以只装"研发卷"或"安全卷"。

## 最后

把一千年前的古籍编纂法，搬到最新的 AI Agent 技能上，这件事本身让我觉得很有意思：
**好的"信息组织"方法论，是跨越媒介的。** 类书当年组织的是经史子集，今天可以组织
的是 prompt 和 workflow。

项目开源、署名优先、欢迎 PR（尤其欢迎帮忙校对采编质量、补互见关系）。
如果你是某个被收录仓库的作者，觉得署名方式要调整，提个 issue 我马上改。

用 Agent 评审 REST API 契约

把现行和拟发布的 OpenAPI 规范交给 Codex 或 Claude Code。让它列出不兼容改动、受影响的客户端和迁移建议，并标明每项结论在规范中的位置。

试跑 OpenAPI 示例

该用哪个技能？

  1. 首选 api-design-principles。适合静态检查资源路径、HTTP 方法、错误、分页和版本规则。技能正文直接提供检查方法和示例。
  2. 备选 api-design-reviewer。可参考它的清单对比新旧 OpenAPI 文件或组织评分报告。仓库缺少它引用的 Python 辅助脚本，自动化评审需要先补齐。

推荐审阅于 2026 年 11 月 15 日。打开互动对比。

试跑 OpenAPI 示例

用两份合成 OpenAPI 文件重现四项不兼容改动和四项设计或安全发现。比如拟发布版本把响应 ID 从字符串改成整数。依赖原契约的客户端可能解析失败，或者丢失前导零。

在 Everything Skills 仓库根目录运行独立的 Node.js 检查器，复跑示例中的契约对比。

node examples/api-review/reproduce.mjs

检查器覆盖本案例的合成输入。实际服务的认证、资源所有权检查和性能需要单独测试。

安装首选技能

Codex

使用 Node.js 22.20 或更新版本，在需要使用技能的项目目录执行。

npx skills@1.7.4 add findscripter/everything-skills --skill api-design-principles --agent codex --copy

Claude Code

在 Claude Code 中运行以下命令，安装「研发工程」分卷。

/plugin marketplace add findscripter/everything-skills
/plugin install 02-engineering@everything-skills

# 技能来源与资源证据

`skill-provenance.json` 覆盖 11 卷全部正式 `SKILL.md`。每条保存本地路径、SHA-256、原创/采编类型、来源声明；可确定参考路径的条目还保存固定提交、文件路径、Git Blob、SHA-256 和近端许可证据 URL。

这些固定参考来自已有来源映射、精确上游名称和不可变 Git 对象，是今后比较与复核的起点。历史采编时没有记录的原始提交仍为 `origin_revision_status: unrecorded`、`origin_commit_sha: null`。本地 vendor 的 HEAD、当前上游 HEAD 或参考文件哈希均不能自动证明原采编版本，也不等于其全部衍生文字已完成许可认证。路径未能确认或有多个候选时明确保留待核状态。

PDF、XLSX、PPTX 在 2026-10-23 因原依赖子目录专有许可而独立原生重写；此前的历史别名映射不再描述其当前正文。PyTDC 按精确技能文件的 MIT 许可澄清，固定历史文件只用于授权复核，不假称已经恢复原采编版本。证据见 `content-corrections-2026-10-23.audit.json`。

维护步骤：

1. 修改技能后，显式运行 `npm run provenance:refresh`。该命令仅扫描本地受控卷、更新本地文件哈希与声明；不会访问网络或执行技能。
2. 来源仓库或源许可声明变化会清除旧参考，标记待复核；正文修改会更新本地哈希，保留既有参考的原本含义。
3. 原始版本不能补证时保持未知。补入参考证据须使用完整 commit、真实文件路径/hash，并核对该文件适用的授权范围。
4. 运行 `npm run check:provenance`、`npm run check:assets`、`npm test` 和对应语言的统一构建。检查命令只读，损坏或缺失清单会报错。

`skill-resources.json` 是已处理缺包技能的资源清单。它分别标记随包资源、完整内联流程和原生重写，记录资源固定来源、字节哈希、许可副本及运行依赖。只验证字节与元数据，不运行第三方脚本、不把库文件伪称 CLI，也不把样例数据计算当作真实平台抓取。

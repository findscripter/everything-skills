# 员工休假期限跟踪

## 何时使用

- 手头有一批**在管（open）休假**，需要把「逼近硬性法定期限、必须现在做决定或动作」的那几条**挑出来**时——典型节奏是**每周一次**复盘（设个周一早上的提醒去跑）。
- 用户说「leave tracker」「休假跟踪」「这几个休假哪个快到期了」「FMLA 指定/证明到没到期」「谁的受保护休假快用尽了」时。
- 需要扫描 FMLA、ADA（便利/互动流程）、州及地方休假法里那些**有日期约束**的节点：休假指定通知（designation notice）、医疗证明（certification / recertification）、用尽与续接、复职/对话窗口。

**不该用 / 边界**：
- **这不是状态看板**。只输出「需要行动」的休假并说清**为什么**；不需要动作的休假每条压成一行带过。把所有休假铺开列状态、做仪表盘，不是本技能的活。
- **不自动定时**。Agent 不会自我排程；周期提醒要靠外部集成（日历提醒、cron、工单系统）单独配。
- **不替律师/HR 拍板**，不出正式法律意见。它告诉你「哪几条该看、为什么、到期日是哪天」，决定由人做。
- **期限天数不凭记忆背**。FMLA 指定/证明的具体天数、各州休假法的通知与时效、ADA 互动流程的「合理」窗口——这些是最容易被编造的点，凡引用到具体规则均须当场研究、引用一手来源，并打 `[来源 — 待核实]`。

## 步骤

### 第 1 步：取数据源

按优先级定位在管休假数据：

1. 若连了 HRIS（Workday / BambooHR / Rippling / ADP）且法务有读权限，从中拉在管休假。
2. 否则读本地登记表 `~/.claude/plugins/config/claude-for-legal/employment-legal/leave-register.yaml`。
3. 两者都没有时，**不要硬编结果**——提示用户上传一份休假表，或把条目手工补进 `leave-register.yaml`。
   每条休假至少需要：员工标识（可只用岗位以脱敏）、休假类型（FMLA / ADA / 州法 / 育儿 / 军役…）、辖区、开始日、已用时长 / 剩余额度、关键节点日期（已发的指定/证明请求日、证明回收截止、复职目标日）。

> **文件读不到时不要静默失败。** 说清原因：路径有误 / 插件按项目作用域安装而文件在项目目录外 / 格式读不了；请用户改正或直接粘贴内容。

### 第 2 步：逐条算「期限信号」并只留需行动的

对每条在管休假，针对当前**有效**规则（研究后引用，见第 3 步）核这几类期限——命中其一即标为「需行动」：

| 期限类型 | 触发判据 | 为何重要 |
|---|---|---|
| **指定（designation）** | 收到休假申请后，雇主须在法定窗口内发指定通知（含资格判定、可用额度告知） | 漏发/迟发会丧失计入受保护额度的能力，留下干扰索赔口子 |
| **证明（certification）** | 已请求医疗证明但回收截止将至 / 已逾期；或到了可发起 recertification 的点 | 证明不全无法合规管理休假；逾期不跟进，后续以「无证明」处理会被翻盘 |
| **用尽（exhaustion）** | 受保护额度（如 FMLA 周数）即将耗尽，需切换到 ADA 便利、州法延续或复职决定 | 「用尽即自动解雇」是高风险动作；用尽点要提前接 ADA 互动流程 |
| **互动流程 / 便利窗口（ADA）** | 已收到便利请求或已知存在障碍，互动对话/决定窗口逼近 | 拖延互动流程本身可构成 ADA 违规 |
| **复职 / 对话窗口** | 复职目标日临近，需准备恢复原岗或同等岗、确认有无医疗限制 | 复职处理不当 → 干扰/报复索赔 |

判完后：**只保留触发了任一期限的休假**作为预警项；其余「干净」休假每条一行总结（如「张三 — FMLA，用至第 6 周，下一节点 8 周后，无需动作」）。

### 第 3 步：研究并引用具体期限规则

对每条预警项里引用到的天数/时效，研究该**辖区当前有效**的规则并引用一手来源、核对时效：

- **不得静默补缺。** 研究工具对某规则返回很少或没有时，报告所得并停下，把信息缺口交给用户决定怎么补，不要用模型知识/网络搜索偷偷填。
- **来源标注。** 每条引用打来源标签：研究连接器（如 `[CourtListener]`/具体 MCP 名）、网络搜索打 `[网络搜索 — 待核实]`、凭训练数据回忆打 `[模型知识 — 待核实]`、用户提供打 `[用户提供]`。带「待核实」的优先核对，切勿剥离标签。
- **辖区识别。** FMLA/ADA 是美式框架；涉及非美辖区时显式声明「美式框架可能不适用」，改走当地休假/病假/产假法。

### 第 4 步：出预警清单

输出**只列需行动项**，每项给：是谁、哪类期限、到期日（含离今天还有几天）、为什么、建议的下一步动作。干净休假折叠成一行清单收尾。

## 指令

- 输出**预警，不是看板**：没有动作的休假绝不展开。
- 每个预警项必须回答三件事：**到期日**（具体日期 + 倒计时）、**为什么是它**（哪条期限触发）、**该做什么**（发指定通知 / 催证明 / 启动 ADA 互动 / 升级）。
- 任何具体期限天数都先研究后引用、逐条打 `[来源 — 待核实]`，不凭记忆。
- 涉及「用尽即解雇」「拒绝便利」「不复职」这类可能引发索赔的动作时，标记 `[需律师/HR 判断]` 并建议升级，不替其决定。

## 示例

触发：
```
跑一下本周的休假跟踪 / leave tracker
```

输出骨架（仅需行动项展开，其余一行带过）：
```
## 休假期限预警 — [日期]

🔴 需行动（N 条）
1. [岗位/姓名] — FMLA 指定通知逾期
   到期：2026-06-03（已逾 1 天）  为什么：申请已收到，须在法定窗口内发指定通知 [来源 — 待核实]
   下一步：今天补发指定通知（资格判定 + 额度告知）

2. [岗位/姓名] — FMLA 即将用尽，接 ADA
   到期：约 2026-06-12（剩 ~1 周受保护额度）  为什么：用尽点临近，需在到点前启动 ADA 互动流程
   下一步：发起互动对话，评估便利可行性 [需律师/HR 判断]

3. [岗位/姓名] — 医疗证明回收截止
   到期：2026-06-06（剩 3 天）  为什么：已请求证明，逾期未回收将影响合规管理
   下一步：今天发催办，告知逾期后果 [来源 — 待核实]

✅ 无需动作（M 条，各一行）
- [姓名] — 育儿假，用至第 3 周，下一节点 5 周后
- [姓名] — 军役假，证明齐全，复职目标日 8 月
```

> 周期提醒需另配：设周一早上的日历提醒来触发本技能；Agent 自身不排程。

## 注意事项

- **只报需行动，不做状态看板**——这是本技能的全部价值，不要被「把所有休假列出来」的请求带偏。
- **不自我排程**：自动周期提醒靠外部集成（日历/cron/工单），不要承诺 Agent 会自己定时跑。
- **期限天数当场研究并引用**，逐条 `[来源 — 待核实]`；FMLA 指定/证明天数、各州休假法时效、ADA 互动窗口是最高编造风险点。
- **不静默补缺**：研究无结果就停下问用户。
- **辖区识别**：非美辖区不要套 FMLA/ADA，显式声明并改走当地法。
- **高风险动作升级**：用尽即解雇、拒绝便利、不复职——标 `[需律师/HR 判断]`，决定交人。
- **数据源缺失**：HRIS 和 `leave-register.yaml` 都没有时，提示补数据，不要凭空生成预警。

## 互见

- requires：（无）—— 可独立使用。
- related：`employment-termination-review` —— 受保护休假用尽后若走解雇路径，转去做高风险旗标审查；`legal-hold-manager` —— 休假纠纷可合理预见诉讼时同步发起证据保全；`general-counsel-advisor` —— 休假法疑难的更上位顾问；`wage-hour-employment-qa` —— 休假与工资工时（如带薪病假折算）交叉问题；`employee-handbook-update-diff` —— 休假政策与手册条款的核对源。
- combines_with：`employment-termination-review` —— 用尽点接「不复职/解雇」决定时合并审查；`general-counsel-advisor` —— 升级休假法判断。

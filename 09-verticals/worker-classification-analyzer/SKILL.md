## 何时使用

在用工关系**尚未开始前**，需要判定拟议的用工形态属于哪一类，并检查「打算用的结构」与「事实实际支持的结构」是否吻合时使用。四种目标形态：

- **雇员（W-2）**：事实在一个或多个适用标准下指向雇佣关系。
- **独立承包人（IC / 1099）**：事实在全部适用标准下都支持 IC。
- **派遣临时工（staffing agency temp）**：工人在中介机构发薪册上，公司是客户；若公司行使日常控制则存在共同雇主风险。
- **供应商 / SOW（公司对公司）**：工人受雇于供应商实体，事实支持时为最干净的结构。

**不该用的边界（硬性）：**
- 关系**已经开始**（哪怕一天）→ 立即停止，本技能不做事后追溯重分类。那是责任评估 + 补救规划（欠薪、雇主侧工资税、福利、失业/工伤追溯、州罚款如 CA PAGA、IRS §530 救济），须由律师主导、享有特权。
- 不起草承包合同 / SOW；不提供误分类已发生后的补救建议。
- **不替代法律本身**：每一个判定标准、法条、判例、阈值、豁免都必须来自针对适用辖区的**当前核查**，本技能只教推理模式，不陈述法律。
- 疑难判断（严格标准辖区、争议要件、既往审计/和解）须人工/外部律师复核。

## 步骤

1. **前瞻性硬闸门（先于任何信息采集）**：先问「这项工作是否已经开始？工人当前是否已在该安排下工作过任何时长？」答案为「是」→ 输出「超出范围—既有安排」说明并停止，建议按升级表升级（通常路由至 GC + 外部劳动法律师）。仅在用户明确说「proceed anyway」时，才以「planning only」口径继续，并在每次输出顶部加 SCOPE MISMATCH 横幅。
2. **加载上下文**：读取配置中的辖区足迹、既往分类历史/和解记录、升级表、公司内部分类政策；按角色加载工作产品头。
3. **Step 1 信息采集（一次性整块提问，勿逐条滴问）**，覆盖四组事实：
   - **工作**：日常做什么；是否属公司核心业务；定义清晰的项目还是无限期持续；技能专业度。
   - **控制**：谁定工时/排班；工作地点；公司是否指导「怎么做」（方法/流程/顺序）还是只管结果；是否监督公司员工。
   - **经济**：计酬方式（时薪/日薪/固定项目费）；工具设备谁提供；是否排他；是否承担财务风险（可盈亏）；是否有自有商业实体（LLC/S-corp/个体）。
   - **安排结构**：直接承包 / 中介派遣 / 供应商-SOW；是否书面合同；时长；是否与员工并肩做同类工作。
   - **分类目的**：联邦工资税 / FLSA / 州工资工时 / 失业保险 / 工伤 / 福利资格——不同目的常适用不同标准，需分轨。
   - **辖区**：工人实际履职地点。
4. **Step 2 确定适用标准**：针对每个辖区×目的，核查当前生效的判定标准（ABC、经济现实、普通法控制权、混合、或目的专属法定标准）。引用受控法条/法规/判例，注明生效日期与近期修订，识别豁免（B2B、专业服务、建筑、转介机构等）。
5. **Step 3 逐要素套用事实**：对每个标准逐要件评分（不可概括），用下方表格结构，要件来自核查结果而非记忆；显式标出争议要件。
6. **Step 4 给出分类 + 差距分析**：给最贴近的分类；若不同目的给出不同答案，明确说明并指出控制性目的与辖区。差距分析是最重要产物，用 🔴/🟡/✅ 对比意图结构与事实。
7. **Step 5 输出 + 闸门**：研究连接器预检；输出工作产品；触发升级条件时升级；非律师用户在出「可按 IC/雇员/中介/供应商推进」终稿前，须过「重大行动闸门」并取得律师明确同意（否则只能出标注 DRAFT 的供律师复核稿）。

## 指令

- **来源标注（不可省略/合并）**：每条引用打标签——`[Westlaw]` / `[CourtListener]` / MCP 工具名（来自法律研究连接器）；`[web search — verify]`（网搜）；`[model knowledge — verify]`（训练知识回忆）；`[user provided]`（律师提供）。带 `verify` 的造假风险高，优先核验。
- **禁止静默补全**：若研究查询对某「辖区×目的」返回很少或无结果，**报告所得并停止**，不得用网搜/模型知识私自填补。按原文给出四个选项（拓宽查询/换工具/网搜并打 verify 标签/标为未核实并停止），由律师决定是否接受低置信来源。
- **升级触发条件**（任一即升级）：严格标准辖区且拟议工作属公司核心业务（无律师复核不得推进）；配置中有既往误分类和解/审计；工人将监督员工或有显著预算权；预计超 12 个月且无明确项目终点；任何会改变分类结论的争议要件。

## 示例

输入：
```
新招一个数据科学家做 6 个月，在我们 SF 办公室用我们的工具，嵌入分析团队。
```
→ 工具公司核心业务 + 公司办公地 + 公司工具 + 嵌入团队，强烈指向雇员；若意图用 IC 结构，差距分析多处 🔴。

输入：
```
我们的招聘顾问承包安排没问题吧？她只为我们工作，自定工时，用自己的笔记本，按成功推荐收项目费。
```
→ 排他性（指向雇员）与自定工时/自有设备/项目计酬（指向 IC）相互冲突，属 close call；按州 ABC 测试可能在 B 要件（是否属公司常规业务范围）失分，须标注争议要件。

要件评分表结构（要件来自核查结果，非本文件）：
```
Test: [标准名称，按核查]
Purpose: [本标准管辖的目的——联邦税/州工资工时/UI 等]
Source: [法条/法规/判例的精确引证]
Currency: [核查截止日期]

| 要件 / 要素 | 采集事实 | 信号 / 通过-不通过 |
|---|---|---|
| [要件1] | [来自采集] | [方向或 pass/fail] |
| ... | | |

测试结构：[多要素权衡 / 连接式逐件必满足 / 混合——按核查陈述]
本标准下结果：[偏雇员 / 偏 IC / 失 X 要件 / 不确定—争议要件]
```

差距分析结构：
```
意图结构：[他们说想要的]
事实指向：[核查标准认定的实际情况]

差距：
🔴 [要件]：[所述] 与 [意图分类] 冲突，因为 [具体标准措辞 + 引证]。若按描述推进存在重大误分类风险。
🟡 [要件]：[所述] 在 [标准] 下是弱项，单独不致命但叠加他项增风险。
✅ [要件]：支持 [意图分类]，无问题。
```

## 注意事项

- **前瞻性是不可协商的**：闸门处含糊的「我猜是吧」不算同意，须重新询问；只有明确「proceed anyway」才以仅供规划口径继续，且全程加横幅。
- **分目的分轨**：联邦工资税适用的标准未必等于州工资工时/失业/工伤的标准，须逐目的各跑一遍，结论可发散。
- **争议要件不可掩盖**：标准能被陈述不代表其适用于本事实已定论；显式标出需律师判断或近期在该辖区引发诉讼的要件。
- **最贵的分类决定，是没人有意识做出的那个**：有人说「要个承包商」就开工，两年后事实看起来像雇佣——本技能就是在开工前把这个错位揪出来。
- 非律师用户出终稿前必须过重大行动闸门；若需找律师，引导其联系所在辖区的执业监管机构（美国州律协、英格兰及威尔士 SRA/BSB 等）转介。
